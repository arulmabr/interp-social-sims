## 1. The design, as three countable facts

`Probes/experiments/_common.py::build_preference_probe`:

| | lottery | ultimatum | capability |
|---|---:|---:|---:|
| distinct prompts | **45** | **19** | **2** |
| samples per prompt | 8 | 8 | 80 |
| training rows | 360 | 152 | 160 |
| **distinct activation vectors** | **45** | **19** | **2** |
| label rule | the agent's own parsed choice on that sample (Risky = 1) | (Accept = 1) | median split of the GPT-5 judge's score of the generated text |
| activation position | final token of the prompt, a separate forward pass, no chat template, no steering | same | same |
| sources of variation across the training inputs | the reward level n, and nothing else | the offer, and nothing else | presence or absence of the persona prefix, and nothing else |
| **split** | **by row** (`StratifiedKFold` over rows) | by row | by row |
| artefact saved | no | no | no |

**The split is by row, and the rows are duplicates.** Each of the 45 lottery prompts contributes eight
identical activation vectors carrying whatever labels the sampler emitted. `StratifiedKFold` shuffles
rows, so every one of those 45 vectors appears in the training fold and in the validation fold of the
same split. There is no prompt-level held-out set anywhere in the code. §3.3's phrase "held-out
preference trials" describes something the implementation does not do.

## 2. The ceiling of knowing n perfectly

For each logged lottery dataset, two accuracies were computed on the choices themselves:

- **ceiling of any function of n** — predict each reward level's majority label. This is the Bayes rate
  for a predictor whose only input is the stimulus, and it is therefore also the ceiling for a probe
  that sees one activation vector per level.
- **best one-parameter threshold rule on n** — "choose risky iff n ≥ t", maximised over t and over both
  directions.

| dataset | ceiling, any function of n | best threshold rule | gap |
|---|---:|---:|---:|
| hosted `baseline` | 0.956 | 0.956 | **0.000** |
| hosted `slightly_prompting` | 0.986 | 0.986 | 0.000 |
| hosted `steering` | 0.986 | 0.986 | 0.000 |
| hosted `lite_steering` | 0.946 | 0.946 | 0.000 |
| vLLM `baseline_rp` | 0.974 | 0.974 | 0.000 |
| vLLM `persona` | 0.981 | 0.981 | 0.000 |
| vLLM `cot` | 0.832 | 0.831 | 0.001 |
| probe L48, all ten targets | 0.961 – 0.972 | identical | 0.000 |

**Two results, and the second is the stronger one.**

1. **A predictor that knows only n reaches 0.95–0.99 on every logged lottery dataset in the
   repository.** The paper's 82% is not above that bar; it is well below it. An 82% probe has learned
   *less* than n, not more.
2. **A one-parameter threshold on n does exactly as well as the unrestricted best function of n** — the
   gap is 0.000 everywhere except one condition, where it is 0.001. Because these choice curves are
   monotone, the majority label per level *is* a threshold rule. So there is nothing for a probe to
   learn beyond "compare n with a number", and 82% accuracy is consistent with a probe that has learned
   a noisier version of exactly that.

**The honest caveat.** The probe's own training labels are not stored, and they came from a sample the
repository does not contain — the probe stack at temperature 0.7 with eight draws per prompt, whereas
these datasets are the hosted stack at 0.5 with forty, the vLLM stack at 0.7 with forty, and the steered
probe stack. The exact ceiling *for the probe's own labels* therefore cannot be computed, only bounded
by the design argument in §1 and estimated by the nearest available data. P8's instruction to save every
artefact from now on is what stops this recurring.

## 3. S1.4(a) and S1.4(c): not available

no logged baseline probe score. The only probe scores in the repository are

The `all` subset is the diagnostic one. Under the shipped script — which scores the *unsteered* prompt
grid, and the same grid at every target — that series must be a flat line, spread 0. It is not: its
spread is 0.442 on Llama and 0.257 on Qwen, and it is well fitted by a line in λ (R² 0.91). Either the
shipped numbers were produced with the hook active and the script is stale, or the script ran and the
series is not what its label says. The repository cannot choose, so neither does this report.
`reports/PROVENANCE.md` §4 carries the same finding for Figs. 11 and 18.

exists:

- **F6-legacy**: the legacy recipe rebuilt on the new stack, named a reconstruction, not the original.
- **F6**: a choice-labelled probe trained on the discovery split where s, p, x, template, order and
  labels all vary.
- Report `cos(F6-legacy, C3)` and `cos(F6, C3)`, where C3 is the reward probe.
- `PREREG.md` should record, **before any benchmark result exists**, the prediction that F6-legacy
  behaves as payoff scaling: belief share dominant, recall and fact-probe decoding of x shifted,
  parallel translation on log x, high cosine with C3.

S1 supports that prediction but does not test it. What S1 establishes is narrower and firmer: the
legacy probe's input is a function of one integer, its reported accuracy is below what that integer
alone buys, and its training protocol has no held-out prompt.
